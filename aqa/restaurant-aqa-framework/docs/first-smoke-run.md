# Перший запуск AQA — крок 5/15

Статус: завершено. Перевірено 3 листопада 2026 року на власному розгорнутому
застосунку Green & Tasty.

## Що запущено

Використано наявний сценарій `A guest can open the home page` із
`Features/Smoke.feature`. Він запускає справжній Chromium через Playwright
для .NET, відкриває UI_URL і перевіряє успішну HTTP-відповідь навігації.

Це базова перевірка доступності через браузер. Вона не перевіряє тексти,
розмітку, вхід офіціанта, бронювання, кошики чи рівні L1–L3.
Тести групового замовлення з таблиці покриття залишаються запланованими.

Код сценарію та фреймворку для цього запуску змінювати не знадобилося.

## Команди

З папки `aqa/restaurant-aqa-framework`, після налаштування локального `.env`:

```bash
dotnet build
```

```bash
PLAYWRIGHT_BROWSERS_PATH="$HOME/.cache/marathon-aqa-playwright" \
PLAYWRIGHT_SKIP_BROWSER_GC=1 \
SKIP_PRE_RUN_CLEANUP=true \
TRACE_MODE=Always \
dotnet run --no-build -- \
  --treenode-filter '/*/*/SmokeFeature/AGuestCanOpenTheHomePage' \
  --report-trx
```

Фільтр вибирає рівно один сценарій. Перед першим запуском автоматично
встановлюються браузери Playwright. Окремий кеш ізолює їх від інших
проєктів на комп'ютері. SKIP_PRE_RUN_CLEANUP=true вимикає загальне очищення
на початку й наприкінці запуску. Сам сценарій не створює тестових записів.

TRACE_MODE=Always задано лише для цього запуску, щоб отримати запис навіть
успішного тесту. У локальному `.env` залишається OnFailureOnly.
