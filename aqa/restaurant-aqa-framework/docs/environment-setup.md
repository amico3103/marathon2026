# Підключення до середовища — крок 3/15

## Локальні налаштування

У папці фреймворку створено локальний `.env` на основі параметрів
`.env.example`. Файл ігнорується Git; доступ до нього має лише його власник.
Паролі та токени в цьому документі не зберігаються.

| Параметр | Значення |
| --- | --- |
| UI_URL | https://d2hntky491rgpt.cloudfront.net |
| API_URL | https://xlwtoyalz8.execute-api.eu-north-1.amazonaws.com/develop |
| BROWSER | Chromium |
| HEADLESS | true |
| DEFAULT_TIMEOUT_MS | 30000 |
| NAVIGATION_TIMEOUT_MS | 45000 |
| TRACE_MODE | OnFailureOnly |
| MAX_PARALLEL_TESTS | 1 |
| SKIP_PRE_RUN_CLEANUP | true |

Початкові запуски послідовні. Паралельне виконання перевіряється на кроці 12.
Автоматичне загальне очищення старих записів вимкнене до перевірки механізму
підготовки та прибирання на кроці 6. Цей параметр не вимикає окремий
CleanupScope сценарію; його дії також потрібно перевірити перед запуском
сценаріїв, які створюють дані.

На кроці 4 заповнено WAITER_*, TESTTABLE_ID і TESTTABLE_WAITER_* для окремого
AQA-офіціанта локації 9 Abashidze Street. Вхід та прив'язку перевірено;
результат — у [перевірці офіціанта](waiter-account-check.md).
ADMIN_* залишено порожніми.

На кроці 6 до локального `.env` додано AWS_PROFILE, AWS_REGION,
AQA_AWS_ACCOUNT_ID і AQA_COGNITO_USER_POOL_ID для точкового прибирання
власних тестових даних. AWS-ключі не копіювалися в `.env`.
Пояснення й результати — у [документі тестових даних](owned-test-data.md).
Облікові записи клієнтів і гостьові сесії для окремих тестів готуються на кроці 6.

## Результат перевірки підключення

Перевірено 3 листопада 2026 року звичайними HTTP GET-запитами:

| Запит | Результат |
| --- | --- |
| Головна сторінка сайту | HTTP 200, отримано HTML застосунку |
| GET /dishes | HTTP 200, коректний JSON зі списком із 8 страв |
| GET /locations | HTTP 200, коректний JSON зі списком із 3 локацій |

Підтверджено, що `.env` ігнорується правилами Git та не перебуває під
версійним контролем. Права локального файла — 600.

Це перевірка доступності середовища, а не запуск AQA-тестів.
Завантаження конфігурації фреймворком, робота браузера й перший тест
перевіряються на кроці 5. Права доступу до груп перевірятимуться окремими
негативними сценаріями.

## Налаштування GitHub на наступних етапах

На кроці 13 workflow має передавати параметри фреймворку через environment:

| Джерело GitHub Actions | Параметр фреймворку |
| --- | --- |
| Variable AQA_UI_URL | UI_URL |
| Variable AQA_API_URL | API_URL |
| Variable AQA_TESTTABLE_ID | TESTTABLE_ID |
| Secret AQA_WAITER_USERNAME | WAITER_USERNAME |
| Secret AQA_WAITER_PASSWORD | WAITER_PASSWORD |
| Secret AQA_TESTTABLE_WAITER_USERNAME | TESTTABLE_WAITER_USERNAME |
| Secret AQA_TESTTABLE_WAITER_PASSWORD | TESTTABLE_WAITER_PASSWORD |

Ці параметри в GitHub ще не налаштовані. Локальний `.env` не завантажується
в репозиторій чи в артефакти запуску. ADMIN_* потрібні лише якщо обраний
спосіб підготовки/очищення дійсно потребуватиме адміністратора.
