# GitHub Actions і звіти — кроки 13–14/15

Підготовлено два workflow в корені репозиторію:

- [AQA Quality](../../../.github/workflows/aqa-quality.yml): збірка, форматування,
  Gherkin lint і перевірка, що знаходяться саме 45 сценаріїв. Запускається при
  push/PR зі змінами фреймворку.
- [AQA Tests](../../../.github/workflows/aqa-tests.yml): реальний запуск усіх
  45 сценаріїв на вимогу або щодня. Обрано `MAX_PARALLEL_TESTS=1`, бо повний
  послідовний прогін 45/45 підтверджено, а два паралельні завершилися
  мережевими помилками. Одночасно виконується лише один CI-прогін.

Публічний артефакт складається з `index.html` і `summary.json`. Генератор
[`ci/publish_report.py`](../ci/publish_report.py) читає TRX, але переносить
лише назву тесту, результат, тривалість і загальну категорію помилки. Сирі
TRX, логи, браузерні траси й журнали тестових даних не завантажуються: у них
можуть бути токени. Публікація відбувається також після помилки тесту; фінальна
перевірка зберігає статус failed. Якщо TRX не створено, звіт прямо це показує
і генератор повертає помилку. Якщо сценаріїв не стільки, скільки очікується,
або не всі пройшли, генератор також повертає помилку. Типовий запуск очікує
45; у ручному запуску можна вказати фільтр і кількість для одного сценарію.
