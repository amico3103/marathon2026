## Особливість порожнього підтвердженого кошика

Звичайне підтвердження порожнього кошика заборонене, а видалення останньої
страви власником скидає ознаку підтвердження. Тому L2-07 перевіряє захисну
гілку сервера на контрольованому тестовому стані, який звичайним UI не створити.

Фікстура спершу створює і підтверджує власний гостьовий кошик через API,
потім очищує лише його `dishes` через DynamoDB. Перед зміною перевіряються
унікальний тестовий клієнт, належність бронювання і столу цьому набору та
зв'язок сесії з групою. Умовний запис перевіряє попередній склад і ознаку
підтвердження. Потрібен додатковий дозвіл UpdateItem для GuestSessions.
Подальший запит підтвердження виконується через справжній API; відповідь
сервера не підміняється. Прибирання — спільний [життєвий цикл даних](owned-test-data.md).

## Як запускати

Після налаштування приватного `.env` і браузерів, з папки фреймворку:

```bash
dotnet build
PLAYWRIGHT_BROWSERS_PATH="$HOME/.cache/marathon-aqa-playwright" \
PLAYWRIGHT_SKIP_BROWSER_GC=1 \
SKIP_PRE_RUN_CLEANUP=true \
dotnet run --no-build -- --treenode-filter '/*/*/*/*[Category=l2]' --report-trx
```

Для одного пункту замість `Category=l2` використовується, наприклад,
`Category=L2-09`. Браузер Chromium headless, послідовне виконання.
Офіціант працює в окремому браузерному контексті. Його trace починається
після входу, щоб не записати постійний пароль. Trace може містити сесійний
токен офіціанта, тому ці локальні артефакти не слід публікувати без перевірки.

## Результат перевірок

Початковий повний запуск 3 листопада 2026: **14 passed, 1 failed, 0 skipped**,
6 хв 1 с. Єдина помилка була в очікуваному тексті тесту L2-09:
виняток сервера повертає `Reservation not found.`, а початковий тест чекав
`was not found`. HTTP-код 404 був правильний. Очікування виправлено відповідно
до класу `ReservationNotFoundException` та фактичної відповіді.

Після цієї правки окремий повторний запуск L2-09: **1 passed, 0 failed,
0 skipped**, приблизно 26 секунд. Усі 15 прикладів L2 мають успішний результат:
14 з початкового запуску та 1 після виправлення тесту. Повторний повний прогін
15 прикладів не потрібен
для зміни одного очікуваного тексту; початковий невдалий звіт збережений.

Початкові результати — `TestResults/step9/initial-l2/`: HTML TUnit, TRX,
BDD-звіт Reqnroll, лог та trace перегляду замовлення офіціантом.
Фінальний [HTML для L2-09](../TestResults/step9/l2-09-final/restaurant-aqa-framework-linux-net10.0-report.html)
і TRX збережено в `TestResults/step9/l2-09-final/`.
Звіти й `.env` ігноруються Git. Публікація артефактів у CI — наступний етап.
Збірка: 0 помилок і попереджень; форматування зміненого C# та Gherkin lint
нового feature пройшли. Застосунок не змінювався, коміт і деплой не виконувалися.

Додатковий запуск L1-09 на фінальній збірці: **2 passed, 0 failed, 0 skipped**,
39 секунд. Він перевірив спільний вибір токенів іншого клієнта та офіціанта.
[HTML регресійної перевірки](../TestResults/step9/l1-09-regression/restaurant-aqa-framework-linux-net10.0-report.html).

зокрема 20, створених у цьому кроці. У кожному журналі `cleaned: true`.

trace офіціанта не виявила налаштованих постійних паролів або секретних ключів.
